# Antigravity 2.0 Agent Guidelines: Ad-ios

Welcome, Agent. This repository contains **Ad-ios!**, a high-performance Google Chrome Manifest V3 ad and tracker blocker designed for macOS and Windows.

When assisting with, refactoring, or extending this codebase, you **MUST** strictly adhere to the following rules, conventions, and architectural standards.

---

## 1. 🚨 Critical Security & Workflow Rules

* **CRITICAL: Never Read, Display, or Stage `private_key.pem`**:
  - The RSA private key (`private_key.pem`) is deliberately excluded from version control via `.gitignore`.
  - **NEVER** use `view_file`, terminal commands (`cat`, `type`, `Get-Content`), or print statements to inspect or display the contents of `private_key.pem`.
  - **NEVER** stage or commit `private_key.pem` to Git.
  - The public key is already safely embedded in `manifest.json`.

* **Strict Git Push Workflow**:
  - **NEVER** execute `git push` automatically.
  - Always commit changes locally first and ask for explicit user permission in chat before pushing to remote branches.

---

## 2. Chrome Manifest V3 Architectural Standards

* **Strict MV3 Compliance**:
  - **Zero Remote Hosted Code**: Never load scripts or styles dynamically from external CDNs. All logic must be bundled locally inside the extension.
  - **Zero `eval()`**: Dynamic string-to-code execution is strictly prohibited.

* **DeclarativeNetRequest (DNR) Ruleset Conventions**:
  - All network filtering rules must reside in `rules/ruleset_*.json`.
  - Maintain the modular category structure:
    - `rules/ruleset_ads.json` (Contextual advertising, ad networks, popups, and interstitials)
    - `rules/ruleset_analytics.json` (Google Analytics, Hotjar, Metrica, and telemetry beacons)
    - `rules/ruleset_images.json` (Ad banner images, GIFs, and media trackers)
    - `rules/ruleset_monitoring.json` (Sentry, Bugsnag, error loggers)
  - Every rule must have a unique numeric integer `id`, a valid `priority`, and a compliant DNR `action` and `condition`.
  - Dynamic rules generated by `scripts/background.js` must use IDs starting at `100000` to prevent collisions with static rules.

* **Cosmetic DOM Filtering Conventions**:
  - `scripts/cosmetic.js` and `styles/cosmetic.css` must inject early at `run_at: "document_start"`.
  - Eliminate layout thrashing by batching DOM inspections with `requestAnimationFrame` and `MutationObserver`.
  - Defuse anti-adblock traps and popunder clickjacking early using defensive JavaScript object stubs.

---

## 3. Build & Packaging Conventions

* **Always Build Using [`build-package.py`](build-package.py)**:
  ```bash
  python build-package.py
  ```
* **Dual Distribution Packages in `dist/`**:
  - `dist/adios.zip`: Clean zip bundle for local "Load unpacked" installations (retains local identity).
  - `dist/adios-webstore.zip`: Dedicated Chrome Web Store submission archive with the forbidden `"key"` property stripped from `manifest.json`.
  - `dist/adios.crx`: Pre-signed CRX3 package compiled using the local Chrome executable.

---

## 4. Enterprise Policy Testing Scripts

* **macOS**: `install-mac-policy.sh` and `uninstall-mac-policy.sh` manage `/Library/Preferences/com.google.Chrome.plist`.
* **Windows**: `install-windows-policy.ps1` and `uninstall-windows-policy.ps1` manage `HKLM:\SOFTWARE\Policies\Google\Chrome`.
* **Crucial Policy Rule**: Always configure `installation_mode = "allowed"`. Never use `normal_installed` without a Web Store update URL, as Chrome will disable the extension and gray out the enable switch.
